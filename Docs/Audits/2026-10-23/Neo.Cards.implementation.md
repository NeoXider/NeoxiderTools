## Published additive API

- `Neo.Cards.IOrderedHandView : IHandView`, `UniTask SetOrderAsync(IReadOnlyList<ICardView> order, bool animate = true, CancellationToken cancellation = default)`. Implemented by built-in `HandView`, consumed by `HandPresenter`. Validates an exact current-member permutation before mutation; no add/remove notifications or reparenting; cancellation stops animation without reverting committed order. Existing `IHandView` remains unchanged.
- `HandComponent.TryAddCardAsync(CardComponent card, bool animate = true)` returning `UniTask<bool>`, plus `TryAddCardAsync(CardComponent card, bool animate, CancellationToken cancellation)`. False means rejection without admission; true records admission even if another caller later removes it. Existing `AddCardAsync` is a wrapper. Admission precedes animation; caller cancellation does not undo an accepted member.
- `CardComponent.FlipDuration` read-only `float`; cancellation overloads returning `UniTask`: `FlipAsync(float duration, CancellationToken cancellation)`, `MoveToAsync(Vector3 position, float duration, CancellationToken cancellation)`, `MoveToLocalAsync(Vector3 localPosition, float duration, CancellationToken cancellation)`.
- Concrete `CardView` adds the same flip/world/local move cancellation overloads, plus `RotateToAsync(Quaternion rotation, float duration, CancellationToken cancellation)` (existing world-space behavior). Concrete `CardViewUniversal` adds flip/world move cancellation overloads. Existing signatures and mandatory `ICardView` members remain unchanged.

## Compatibility and design decisions

- Existing public signatures, serialized field names, enum values and `CardData` equality remain. No asset rewrite, new package dependency or mandatory scene setup.
- Superseded/cancelled concrete move/flip/rotate operations report `OperationCanceledException` and no success event. Internal layout replacement finishes quietly; caller/destruction cancellation remains observable. Drunkard's public round task finishes quietly when its game is replaced.
- Add/place notifications occur after layout only while that exact admission still belongs to its owner. Cancelled animation preserves committed membership. A deck reset now preserves cards already accepted by a hand; explicitly zero flight duration overrides configured flight duration. Board removal compacts remaining slot indices to current membership order. These behaviors are documented for 11.0.
- NI12 makes reset survival hold inside the same admission/draw observer, rather than only after the enclosing call returns. Replaced deals emit no old success or duplicate rollback. Presenter callbacks from superseded async operations are suppressed; completed ordinary operations keep their normal events. Serialized null slots retain their former no-motion admission behavior.
- I21 extends that handoff to the earlier native reparent boundary. A parent/children callback now sees actual accepted component/model membership and released source cleanup ownership. Parenting moves within the existing accepted callback, before public model events, preserving their observer-visible parent and the previous accepted-history result. Rejected calls keep their original parent/cleanup ownership. No serialized/default/equality change.
- Reused existing models, `HandModel` admission/capacity, DeckModel return operations, layout calculator/settings, UniTask and DOTween. `CardTweenScope` is an internal operation-lifetime helper, not a zone/transaction framework. P01 instance IDs, zones, reservations and a pure Drunkard model remain proposals in the unchanged plan; only its approved optional ordering portion was implemented.
- Mixed direct logical draw/shuffle with a visual stack remains the documented synchronization limitation. Direct mutation of the exposed Model bypasses the component's generation/visual ownership contract. No atomic cross-zone framework or FPS measurement is claimed.
