5b. The style engine considers only rules with an empty `AtContext`.
7. Number text is `CssFormat.Number` (`0.####`, invariant, `-0` becomes `0`), `0px` prints as `0` (oracle parity), `CssColor.ToText()` returns the authored text when present else `rgb(r, g, b)` or `rgba(r, g, b, a)`.
8. `DiagnosticBag.Sorted()` order: severity descending (Error first), file ordinal, line, column, rule id ordinal, insertion order.
9. UXML writer layout (Core): header `<?xml ...?>`, `<ui:UXML xmlns:ui=... xmlns:uie=... editor-extension-mode="False">`, then `ui:Template` elements, then `Style` elements, then the roots. Element types without a prefix get `UxmlWriterOptions.DefaultPrefix`; a type containing `:` keeps its prefix.
10. Namespace `HtmlToUitk.Convert` shadows `System.Convert` inside any `HtmlToUitk.*` code: write `System.Convert.ToInt32(...)` explicitly.

## Core API summary (available since 2026-10-08T16:50Z, `dotnet build src/HtmlToUitk.Core -c Release`)

HTML: `new HtmlParser().Parse(text, path, sink)` gives `HtmlDocument`: `Body` is the virtual root (tag `body`, attributes of the real body; its children have `Parent == Body`; `Body.Parent == null`), `HtmlAttributes`, `Title`, `Metas`, `Links`, `StyleBlocks`, `Scripts`, `Templates` (detached from the tree), `StyleOrder` (document order of `<link rel=stylesheet>` and `<style>`; `Index` points into `Links` or `StyleBlocks`). `<meta> <link> <style> <script> <title> <base> <template>` never appear in the tree. `StyleBlock.Span.Start` is the position of the first character of the CSS text: use `new CssParser().Parse(text, path, origin, sink, block.Span.Start)` so diagnostics carry page coordinates. HTML recovery diagnostics (Warning, not in rules.json, root may add them): `H001` end tag without start tag, `H002` element not closed, `H003` unterminated comment/tag/attribute/raw text, `H004` self-closing syntax on a non-void element (ignored, as browsers do), `H005` nesting deeper than 512 (Error). Text nodes are kept as authored (entities decoded); whitespace-only text between elements is kept except before the first content.

CSS: `CssParser.Instance.Parse(text, path, origin, sink)`; syntax errors `C029`, nested rules `C028` (both Error). Values are typed (`CssValueParser.Parse`), `rgb()/rgba()` become `CssColor` (text canonical `rgb(r, g, b)` or `rgba(r, g, b, a)`; hex and names keep authored text), `0px` prints `0`. `SelectorParser.ParseList/Parse/Format`, `SelectorMatcher.Matches(selector, element, states)` (states apply to the subject, `Hover` and `Active` also to ancestors), `ShorthandExpander.Expand/TryExpand(decl, ShorthandOptions.Default|Cascade)` (omitted parts are not emitted by default, `Cascade` emits `initial`; transition and animation always fill defaults so lists stay aligned), `UssWriter.Write(sheet, options)` (oracle layout: one selector per line, 4 spaces, blank line between rules, canonical property order of the oracle `GROUP_ORDER`), `UssPropertyOrder.Sort`.

Style: `new StyleEngine().Build(cascade, options, sink)` returns a `StyleModel` (public class; cast to use `ResolvePseudoElement(element, "before", states)` and `MatchingRules(element, states)`). Resolve applies: var() substitution, shorthand expansion, specificity then sheet order then rule order then declaration order, `!important`, inherit/initial/unset, inheritance of the UI Toolkit inherited set (`StyleEngine.DefaultInherited` or `StyleOptions.InheritedProperties`). Only rules with empty `AtContext` apply. A declaration whose var() cannot be resolved is dropped (an earlier valid declaration wins). Build reports: `J001` Warning per conflicting selector+property across sheets (Span = later declaration, Related = [earlier, later]), `C033` Error for undefined var() without fallback and for var() cycles.

UXML: `UxmlReader` (U001 Error on XML problems, DTD prohibited, depth cap 256, `ui:` stripped from `UxmlType`, `uie:` kept), `UxmlWriter` (layout fixed in note 9 above, attribute order as given), `UxmlElementEditor(document)` implements `IElementEditor`.

JSON: `JsonReader.Parse(text[, JsonReadOptions])` (strict, depth 64, duplicates are an error by default, `JsonParseException` with line/column, `TryParse`), `JsonWriter.Write(value, JsonWriteOptions.Pretty|Canonical|Compact)`, ordered `JsonObject`, typed getters, numbers keep their raw text.

### Traps found
- Do NOT write C# with backslash character literals through bash heredocs, `sed` or `python -c`: the tool rewrites them (a backslash-backslash literal becomes a single backslash, `¬` becomes `00ac`, a NUL byte can appear). Use the Write and Edit tools. Helper to replace one line by number: `python -I Scratch/HtmlToUitk/fixline.py <file> <line> "<new text>"` (it normalises CRLF to LF; no backslashes in the text).
- Never run `taskkill /IM dotnet.exe`: it kills the other workers' builds. This worker did it once at about 17:00Z to stop a hung test, so W2, W3 and W4 may have seen a failed build around that time and only need to re-run.
- Inside any `HtmlToUitk.*` namespace the name `Convert` is the namespace `HtmlToUitk.Convert`: write `System.Convert.ToInt32`.
- `CssChars.StartsIdent` and `CssChars.ReadIdent` must stay consistent (a lone trailing backslash is not an identifier start), otherwise parsers loop forever.
- `Stylesheet.Rules` includes rules nested in `@media` (their `AtContext` is non-empty); anything that must ignore conditional rules has to filter on `AtContext.Count == 0` (the style engine and `UssWriter` do).
- `:root` matches the virtual body (`Parent == null`), not the top-level elements; top-level elements have `Parent == Body`.
- `rgb()` and `rgba()` become `CssColor` whose `ToText()` is canonical (`rgba(30, 58, 58, 0.8)`), hex and named colours keep their authored text; `0px` prints as `0`; numbers use `0.####`.
- nth-child canonical text: (2,1) prints `odd`, (2,0) prints `even`, otherwise `An+B` without spaces.
- A diagnostic on CSS text inside `<style>` only has page coordinates if the CSS parser is called with `StyleBlock.Span.Start` as the base position.
