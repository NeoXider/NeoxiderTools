## Завершённая работа и долг проверки

Аудит охватил 75/75 C# файлов. Уже исправлены F01–F16: типизированные коллекции drawers, безопасность поиска/сохранения Missing Scripts, неоднозначные имена объектов, disabled-кнопки, повторный вызов inspector callback, коллизии перегрузок, выбор asmdef, ZIP, освобождение временных графических ресурсов, отмена/имена Singleton Creator, GUI layout, высота Power, числовые preview, generic-методы и relay-кандидаты. Float relay допускает `float`/`double`, исключает интегральные параметры. Повторно реализовывать эти исправления не требуется.

Результат: 15 исходников, девять публичных страниц, пять новых файлов регрессий с 28 NUnit cases. Фактически выполнены статические проверки: scoped diff/whitespace, UTF-8 для 102 файлов, ссылки 16 страниц, уникальность пяти GUID, границы владения, размещение тестов и отсутствие добавленных obsolete ID API. CLR metadata probe проверил подбор числовых перегрузок. Unity-компиляция, NUnit/IMGUI, Mono reflection и графический lifecycle **не запускались**; наличие теста не означает его прохождение.

## Существенное улучшение P2: сервис Missing Scripts — предложение

Сейчас scan/repair связан с GUI; `RemoveAllMissingScripts` повторяет загрузку/сохранение для каждого результата. `FindObject` использует sibling indices + имя: перестановка одноимённых соседей после scan может изменить адресат. Это риск по исходнику, воспроизведение в Unity ещё отсутствует. `Editor/Tools/PrefabMissingScriptUtility.cs` дублирует traversal и имеет другие save/count semantics.

Предложить публичный editor-only C# API в существующей `Neo.Editor`, namespace `Neo.Editor.Tools`:

- `MissingScriptScanService.Scan(AssetScanRequest)` возвращает последовательность `MissingScriptScanStep`; caller выполняет её на main thread и отменяет между шагами.
- `BuildRepairPlan(IReadOnlyList<MissingScriptFinding>)` создаёт неизменяемый план; finding содержит GUID, устойчивый object identity, display path и revision.
- `ApplyRepairPlan(MissingScriptRepairPlan, OpenSceneSavePolicy)` возвращает `MissingScriptRepairReport` с отдельными repaired/stale/failed/cancelled результатами; default — `LeaveDirty`.

Новые файлы: `Editor/Tools/MissingScriptScanService.cs`, `MissingScriptRepairPlan.cs` (модели/группировка), `MissingScriptAssetStore.cs` (Unity adapter). Переиспользовать preview/additive scene handling, prefab contents, Undo и cleanup из `Editor/GUI/FindAndRemoveMissingScriptsWindowGUI.cs`; подключить этот GUI и `Editor/Tools/PrefabMissingScriptUtility.cs` как адаптеры. Существующие меню, `FindAndRemoveMissingScriptsWindow`, публичные utility signatures и единицы возвращаемых counts сохранить; legacy `RepairOpenScene()` задаёт свою явную save-policy, новый API/окно оставляет открытые сцены dirty.

Реализация: сначала тестируемые модели/группировка и adapter seam; затем проверить local file ID/GlobalObjectId для preview/prefab в поддерживаемых Unity; только после этого зафиксировать identity-контракт и публичный API. Неоднозначный identity возвращает отказ, без fallback по имени. Перед записью проверять disk revision и актуальность live-объектов; изменённый результат требует повторного scan. Группировать по asset, загружать/сохранять один раз; закрывать только принадлежащие операции ресурсы, сохранять доступ к несохранённой работе при ошибке.

Корни передаются данными запроса: developer `Samples`, release `Samples~`, импортированный `Assets/Samples/NeoxiderTools/<version>/<sample name>`. `Samples~` не считать AssetDatabase-папкой: для ремонта предложить импорт, вернуть явный unsupported-root результат. Файлы, GUID, сцены и serialized поля пользователей не мигрируют; новой runtime-зависимости/asmdef не требуется.

Минимальная приёмка `Audit20261023NeoEditorMaintenanceTests.cs`: 100 findings одного asset дают одну загрузку/запись; rename/reorder/delete делает план stale; дубликаты и `/` разрешаются однозначно; cancel/exception освобождает owned resources; read-only/save failure отражается в отчёте; dirty multi-scene setup и active scene сохраняются. Fake store проверяет группировку/отказы, EditMode fixtures — реальные scene/prefab persistence и Undo. Документация: `Docs/Editor/FindAndRemoveMissingScriptsWindow.md` и `README.md`, пример C# scan→plan→apply и Inspector workflow. Оценка: 3–5 дней, средний риск identity/version API.

## Порядок интеграции и критерий завершения

Сначала локальные P1 guard/path и регрессии; параллельно владельцы уточняют C1/C2. Затем модели/тесты maintenance, API и Unity adapter, GUI/facades, интеграция runtime-контрактов, публичные RU/EN docs, проверка UPM layout/import. Prefix всех новых editor-тестов — `Audit20261023NeoEditor`; новые asset-файлы получают уникальные `.meta`. Общие конфигурации меняет только координатор при доказанной необходимости.

Централизованно выполнить уже добавленные 28 cases и новые проверки; графические IMGUI/GPU cases запускать с графическим контекстом, skipped не считать pass. Дополнительно проверить modal Cancel/close и GUI focus/layout. Скомпилировать Unity 6.0–6.4 и 6.5+, ветки MIRROR off/on; обе версии ID API проверяются своей версией компилятора. Использовать существующий `NeoComponentHealth.StableId`, без рассыпанных version gates. Для чисто editor-изменений достаточно EditMode; сетевой lobby требует PlayMode/two-peer проверки, runtime occurrence — тестов его владельцев.

Наблюдения о timeout/reload update-checkers и статических inspector textures остаются непроверенными рисками, не подтверждёнными утечками; отдельный lifecycle эксперимент предшествует исправлениям. Завершение реализации: перечисленные acceptance выполнены, сохранена совместимость API/assets, docs соответствуют поведению, результаты по версиям и пропуски явно записаны. Открытые решения — доставка lobby sample и runtime occurrence-контракт; они не блокируют независимые исправления. Само написание этого плана не закрывает Unity verification debt.
