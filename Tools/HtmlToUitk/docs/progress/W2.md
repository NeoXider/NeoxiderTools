### Traps found (do not rediscover)
- Generated names are `htu-<role>-<Fnv.Hex8(key)>` (`NameGenerator`): grid and gap key = selector text of the rule that declares `display: grid` or `gap` (`.gr__grid`), cell classes append `-<k>` (distinct declaration block, first-use order), static-selectors key = pseudo text from `SelectorParser.FormatCompound` of a compound holding only that pseudo (`:is(.sl__a, .sl__b)`), sibling key = left compound + space + combinator (`.sa__a +`), attribute key `[type="text"]`, pseudo-element key = canonical selector text (`.pe__chip::before`). All verified against the fixtures.
- Markers and generated classes go on the UXML elements matched by the PREFIX of the original selector, evaluated on the HTML DOM (`TransformState.MatchDom`); later emulations match rewritten selectors on the UXML tree (`MatchUxml`).
- Generated rules are inserted right AFTER the rule that declared the construct (`RuleOps.InsertAfter`), never at the end; the emptied original rule disappears in the final dedupe (`Dedupe` drops rules without declarations).
- Section ordering: `UssLayout.Order` falls back to source order when a higher-section rule precedes a lower-section rule that CONFLICTS with it and has the same specificity; "related" means same property or shorthand vs one of its longhands (NOT two different longhands: that is why S26 passes, the oracle's wider relation was narrowed).
- Declaration canonical order and the layout/components/states/utilities classification are a port of the oracle (`UssLayout.GroupOrder`); custom properties first, unknown properties after the known groups in source order.
- Attributes are sorted by `AttrOrder` (name, text, label, title, class, value, ..., unknown names alphabetical, `style` last). Elements created by emulations must use `ElementEditor.Create`.
- The translator never reports diagnostics; Rules (W3) owns them. Emulations report only what Rules cannot see (E001 after a failed transform) through `TransformState.Report` (it skips duplicates). If Rules predicted E001 the planner returns Reject with no EmulationId and the emulation is not invoked.
- Value emulations (relative-units, viewport-units, calc-fold) rewrite CSS declaration text before translation; a `calc()` that cannot be folded drops the declaration. `em` uses the rule's own `font-size` or the computed size of the first matching element; `rem` uses `ConfigExtras.RootFontSize` (default 16).
- The style engine expands shorthands in `Resolve` (gap to row-gap/column-gap, overflow to overflow-x/overflow-y), so emulations read the longhands through `TransformState.Prop`; `overflow: auto` (shorthand source) maps to a vertical ScrollView, explicit `overflow-x` alone to Horizontal, both explicit to VerticalAndHorizontal.
- `ResolvedValue.Rule` is the ORIGINAL parsed rule: use it for selector text and locate the working copy with `RuleOps.Same` (span + selector text).
- Skin `Style src` is the authored `data-uss` text; the tokens file path comes from `config.Output.TokensFile` (`Skin/<Name>.tokens.uss`) and is referenced before the first non-skin sheet; `uss.tokenScopeSelector` adds a scoped token block as the first rule of the page USS (`Assembler.ScopedBlock`).
- Diagnostics file names: Core spans carry the path as given in the job (relative to the job directory).
