## Design decisions

- Package `unity/com.neoxider.htmltouitk`: Runtime (UnityEngine only), Editor, and a separate adapter assembly `Adapters/NeoxiderUiKit` (own asmdef with `defineConstraints: NEO_UIKIT` set by `versionDefines` on `com.neoxider.uikit`; keeps the Runtime assembly free of an optional reference).
- Every algorithm that does not need UnityEngine lives in `Runtime/Logic/**` and `Editor/Logic/**` (no `using UnityEngine`); `Tests~/PureLogic` compiles exactly those files with dotnet and runs NUnit.
- Runtime has its own tiny JSON reader/writer (`Logic/Json`): `JsonUtility` cannot read free-form objects (`set`), and the Core DLL is Editor-only.
- The Editor bridge never references the Core DLLs at compile time: in-process is found by reflection (so the package compiles before the DLLs exist), CLI process is the fallback. Both return diagnostics.json text, parsed by `DiagnosticsReport`.

## Seams and open items for root

- In-process runner contract: a public static `int Run(string[] args, TextWriter output, TextWriter error)` on `HtmlToUitk.Convert.Jobs.JobEntry` (or `HtmlToUitk.Convert.JobEntry`, `HtmlToUitk.Cli.CliApp`, `HtmlToUitk.Cli.CliEntry`) in a netstandard2.1 assembly that is copied into `Editor/Plugins`. It must accept `run <job> --format json [--validate-only] [--force]` and print `diagnostics.json` to the output writer. The CLI project is net8.0 and cannot be loaded by Unity, so the shared entry must live in Convert (or another plugin DLL) and `Cli.Program.Main` should only forward to it.
- Relative paths in a job (`inputs.*`, `config`, `output.root`) are assumed to resolve from the folder of the job file (as in `examples/main.htujob.json`); the window and the temporary per-run job copy rely on it. Architecture 6.2 shows `Assets/UI/Generated` as `output.root`, which only works from the project root.
- `nav.json` semantics implemented (and tested): `show` replaces the top of the stack, `push` appends, `back` closes the topmost modal first, then pops, `BackOnRoot` at the root; `uitk-prototype.js` should match this. NeoxiderUiKit backend uses the layered variant (`ShowClearsStack`, `PushKeepsPreviousVisible`).

## Wording for the architect (spec/schemas, docs)

- job.schema.json, description of the root object or of `inputs`, `config`, `output`: "Every relative path in a job file (inputs.*, config, output.root, output.folders.*, output.perFile keys) is resolved against the directory that contains the job file. Absolute paths are used as they are."
- nav.schema.json, `edges[].mode`: "Default is push. push appends the target page to the back stack, show clears the back stack and makes the target the only entry."
- nav.schema.json, `pages[].transition`: "in is used when the page is the target of a navigation (together with edge transition, which wins), out when the page is left by back; ms is the duration for both, default 220 ms; default transition is fade. Modals use fade, 150 ms."
- diagnostics: "The report is written to <output.root>/diagnostics.json; with --format json the same object is printed on standard output. Exit codes: 0 PASS (also PASS WITH WARNINGS unless --strict), 1 FAIL (or warnings with --strict), 2 usage or I/O error."
- nav.json notes for NavMapWriter: modal close triggers are the `data-close` elements of the modal; a trigger inside an open modal closes that modal, `closeModal` edges are optional.
