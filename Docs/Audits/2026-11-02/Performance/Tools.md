## Existing measured evidence

[InteractionPerformanceBaseline](../InteractionPerformanceBaseline.md), [native interaction review](../NativeInteractionExecutionReview.md) and [native input polling review](../NativeInputPollingPerformanceReview.md) retain the root-owned evidence: 12 raw captures/readbacks, 120 selected positive and 120 stable-miss frames per configuration, Unity **6000.3.14f1 Editor / D3D11 / virtual input / Profiler enabled**. These are Editor measurements, not Player, physical-device or other-SDK acceptance.

- Stable contexts already share **one native query**. Dense camera 3D, N=1,000 targets and H=1,000 hits: classification p50 **937.92565 ms**, AutomaticUpdate p50 **955.59880 ms**. Nested markers must not be summed. Classification remains measured/open under CLI02; its external index/live-ownership/complete-fallback work is not accepted here.
- Keyboard AutomaticUpdate GC is **3,384 × N bytes per selected frame**, in both positive and stable-miss phases. This is measured/open under CLI01. Camera AutomaticUpdate GC was zero in those captures; all-thread GC was separately nonzero. Mouse dispatch, extension picking and movement are not thereby certified.
- The **123 interaction functional cases** establish functional evidence within their recorded scope, not performance closure. Other functional passes in the existing audit likewise supply parity oracles, not timings.
- `GC.GetAllocatedBytesForCurrentThread` returned **0 for a 4,096-byte calibration payload**; old zero-allocation assertions using that counter are invalid. Native raw Profiler metadata observed **4,096 → 4,128 bytes**. No new counter result is asserted here.

## Five leading measurements — proposals only

Common execution contract for the owner: reuse the root raw Profiler capture/readback workflow and existing fixtures; baseline on Unity 6000.3.14f1 Editor/D3D11 with exact installed Input/URP/DOTween graph recorded. Record product source hashes, settings, fixed timestep, time scale, frame IDs, workload counts and capture options. Other Unity versions, build backends and Players need separate results.

Warm code/collections/pools and positive behavior first. For each sustained condition select **120 admitted positive frames and 120 stable-negative/control frames**, recording actual physics ticks and operations; record one-shot/cold costs separately as a known operation count. Retain transition frames separately. Read back library method subtrees or use owner-added narrow markers in a future authorized change; record CPU p50/p95, GC bytes/allocation count and native call counts. Missing samples/markers, frame gaps or count mismatches invalidate the window. Keep frame/operation logs, assertions, reflection invocation, reference queries, serialization of benchmark output and disk writes outside measured scopes; distinguish SDK/Canvas work caused by the product from harness work. Calibrate native GC metadata with a retained 4,096-byte payload and an empty control, record actual readback; do not reuse the failed managed allocation counter. Record live objects/materials/managed references before warmup and after owned teardown/native destruction frames. Preserve complete result and callback parity, with no invented timing cutoff.

## Disposition and read boundary

**Measured confirmed bottlenecks:** only the linked root interaction classification and keyboard polling findings; their corrections remain with CLI02/CLI01. **Source-confirmed repeated work, unmeasured cost:** Drawer full smoothing/collider copies, Selector set/snapshot synchronization (including getters), Spawner linear tracking/pruning, interval-driven native navigation and per-controller grounding, coroutine/format/picking/timer publication work described above. Their actual ranking is unknown.

**Plausible risks requiring measurement:** native query and Canvas/SDK setter cost, callback amplification, pool collection-check cost, iterator/boxing contribution, retained diagnostic keys and saturation-induced magnetic membership churn. **Intentional/approved costs and limits:** complete explosion/ground/interaction fallbacks; magnetic capacity and coupled force cadence; ownership/reentry snapshots; explicit formatting/layout/save/authoring work; prewarm lifecycle; same-index selector publication. None is a newly established functional defect or a blanket zero-GC promise.

Actually inspected: the named implementation ranges/callers in the 16 rows, extension entry README, magnetic capacity/cadence documentation and prior audit disposition; selected current regression source for Draw geometry/leases, physics Play admission/compound force, ground saturation, navigation cadence/NoPath, pool lifetime/Play setup, selector input/bounds and timer mutation. Other fixture names/results were reused from the existing audit/root evidence rather than reread as full files. Ground's existing Edit fixture uses reflective private-method invocation and a complete native reference: useful parity, not FixedUpdate timing. Navigation/physics fixtures admit real Play/NavMesh/physics before their relevant assertions; their growing submission/result lists and setup reflection must stay outside any measured product scope. No benchmark driver, test, candidate or product implementation was created or changed.
