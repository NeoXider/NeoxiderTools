## Module and integration boundary

- This is a separate pair of Unity assemblies, `Neo.HtmlToUitk.Runtime` and `Neo.HtmlToUitk.Editor`, inside `com.neoxider.tools`; it is not a separate UPM package. Runtime references `Neo.Extensions`; Editor references Runtime and is Editor-only. The converter/CLI lives separately under `Tools/HtmlToUitk`, outside Unity's `Assets` tree.
- The public converter route is `CliApp.Run` → `JobEntry.Run` → `JobRunner.RunFile/RunSpec` → load/analyse/plan/transform/emit → addressed output writes. `validate` does not commit conversion outputs; unsupported `preview`/`compare` return nonzero. `--force` is explicit and must not be used to manufacture an acceptance pass.
- The Unity integration route is `HtmlToUitkRunner` → a selected `IJobBridge` → a fresh report validated against this request → addressed refresh/import. `CliProcessBridge` owns its launched process, timeout and bounded stream cleanup; the reflection-based in-process bridge requires actual converter DLLs loaded in the Editor.
- No converter DLL is tracked in `Editor/Plugins` at this baseline; its `README.txt:1–4` explicitly requires copying a built plugin or using the external CLI. An `AssetDatabase.ExportPackage` of package assets alone does not distribute `Tools/HtmlToUitk` outside `Assets`. Release needs an explicit, tested companion-tool/plugin prerequisite and fresh-consumer setup; no mandatory module extraction or third-party redistribution is requested.
- The generated runtime path is typed public API: `UIDocument` + imported `VisualTreeAsset`, `UitkScreen.Configure(document, nav, anim, media)`, optional `ILocalizer`, `RegisterAction` leases, Router/Animator/Breakpoints. A `.runtime.json` file's presence alone does not instantiate a scene component or prove input/rendering behavior.

## Confirmed findings

### HTU-IR01 — P1: distinct generated outputs can silently collapse to one path

**Location:** `Tools/HtmlToUitk/src/HtmlToUitk.Convert/Pipeline/Assembler.cs`, `AssignNames:222–245`, shared-sheet allocation `55–70` and emission `148–154`; `Pipeline/EmitStage.cs:57–89`; `Emulations/Sinks.cs`, `AssetSink.Add:22–28`.

**Trigger and actual result:** names allocated in sorted input order as `home`, `home`, `home-2` become `home`, `home-2`, `home-2`: the allocator reserves the original key but not its generated suffix. Per-file output-name overrides expose this independently of source screen-name validation. Two distinct shared CSS groups whose source files are both named `common.css` also select `Shared/common.uss`; `emittedPaths.ContainsKey` drops the later group without comparing group/content. `EmitStage` then sorts and silently retains only the first identical `RelativePath`. A successful conversion can therefore omit a page or stylesheet and leave references selecting the wrong content.

**Related manifest/path boundary:** `AssetSink` keys raw strings and returns an existing path without payload equality; output emission normalizes asset paths, while manifest deduplication uses the original strings. Distinct payloads at `Generated/a.png`, `Generated\\a.png`, or `Generated/./a.png` can collapse to one output while generating conflicting manifest identities. Case aliases matter on the release target filesystem. The built-in gradient baker uses full SHA256 names; this review does not allege a weak gradient-name hash collision.

**Smallest repair:** reserve actual canonical emitted identities, including generated suffixes, across relevant output kinds; deterministically disambiguate legitimate names or reject unequal-content collisions with a nonzero actionable diagnostic. Same canonical path plus identical bytes can remain idempotent. Preserve group identity and protect reserved manifest/output paths. No transaction framework or public API redesign is required.

**Required controls:** three-page suffix collision; two distinct same-stem CSS files with both cascades observable; same-byte alias idempotence versus unequal-byte alias rejection; slash/dot/case aliases and generated-manifest/cross-kind collision. Assert complete output/reference/manifest content, not merely a nonempty output directory. Owner: `audit_extensions`.

### HTU-IR02 — P2: callbacks can publish or clear a superseded screen projection

**Location:** `Assets/Neoxider/Scripts/UI/HtmlToUitk/Runtime/Navigation/UitkScreen.cs`, `Rebuild:97–130`, `Disconnect:91–95`, `TeardownProjection:132–142`; `Localization/ILocalizer.cs`, `Apply:35–44`; `Animation/UitkAnimator.cs`, `Dispose:213–220` / `Finish:367–382`.

**Trigger and actual result:** an `ILocalizer.Resolve` callback synchronously calls `ConfigureRoot(B)` or disables the component while outer `Rebuild(A)` is at `Relocalize:103`. The outer call resumes and assigns A's Breakpoints/Animator/Router after B or disconnect has completed. Reentry can happen earlier: teardown disposes an animator, whose public `Cancelled` observer replaces the root; outer `Rebuild:99` then overwrites the replacement. Teardown's `_backend = null:142` also runs after callback-producing disposal and can clear the newer backend. The existing connection-generation fence protects constructor adoption, not these projection continuations. An exception from stale work can similarly reach catch cleanup against a newer projection.

**Smallest repair:** private projection generation/ownership fences around callback-producing teardown, localization, animation startup/reduced-motion callbacks and subsequent publication; detach owned fields before disposal callbacks; stale catch/tail must not tear down or unbind the latest projection. Preserve the existing public API and ordinary navigation/action order.

**Required controls:** real attached-panel localizer A→B replacement, disable/destroy during resolution, and animator-cancellation A→B replacement; B remains the current root/router/action owner, old media/animation/trigger leases stop, ordinary subsequent reuse/navigation still works. Owner: `audit_extensions`.

### HTU-IR03 — P2: converter-accepted localization keys are rejected at runtime

**Location:** `Tools/HtmlToUitk/src/HtmlToUitk.Contracts/Config.cs:29`; `HtmlToUitk.Rules/Checks/LocalisationRules.cs:176,218–222`; `Assets/Neoxider/Scripts/UI/HtmlToUitk/Runtime/Localization/ILocalizer.cs:23,35–44`.

**Trigger and actual result:** the converter's default key pattern accepts `app.Home.Title`; the runtime's lowercase-only `LooksLikeKey` rejects it, so `Resolve` is never called and the generated key remains visible. Even an explicitly supplied `LocalizationKey` is sent through the same rejecting heuristic.

**Smallest repair:** align default runtime recognition with accepted default converter keys and honor an explicit key marker; retain ordinary literal text behavior and document any custom converter-pattern boundary rather than silently narrowing existing accepted input.

**Required controls:** accepted mixed-case key through conversion → runtime Resolve → repeated relocalization; explicit marker; lowercase positive; literal text negative. Owner: `audit_extensions`.
