# Neo.Tools.Text: индивидуальный план реализации

Фаза 2, тот же аудитор; модель/режим по контракту: `gpt-6.1-sol`, `max`. Основание: завершённый аудит `Neo.Tools.Text.md`, точная запись manifest и текущие исходники, документация, регрессии и границы зависимостей. В этой фазе создан только этот план; Unity, сборки и тестовые процессы не запускались.

Полностью проверены оба файла сборки: `Assets/Neoxider/Scripts/Tools/Text/SetText.cs` и `Assets/Neoxider/Scripts/Tools/Text/TimeToText.cs`. Обновлены существующие `README.md`, `SetText.md`, `TimeToText.md` в `Assets/Neoxider/Docs/Tools/Text/`. ## Оставшиеся исправления и долг проверки

**P2, D1 — подтверждённое чтением исходника несогласованное переключение режима; Unity-воспроизведение ещё не выполнено.** В `TimeToText.DisplayMode` значение `_displayMode` записывается до `UpdateDisplay()`. Последующий `Set(CurrentTime)` отклоняет длительность за пределами Clock. Воспроизведение: выбрать Compact, отключить `CompactUseTimeFormat`, вызвать `Set(3000000000f)`, затем присвоить `DisplayMode = Clock`. По текущему потоку управления свойство становится Clock, но подпись остаётся `34722d 05h 20m` и время не меняется. Это противоречит обещанию свойства перерисовать текущий формат.

Владелец — `Neo.Tools.Text`. Минимальное исправление: проверить текущую длительность для предлагаемого режима до изменения состояния; недопустимый переход сохранить целиком в предыдущем состоянии. Не обрезать принятое время до Clock-предела. Изменить только `TimeToText.cs`, добавить случаи в `Assets/Neoxider/Tests/Edit/UI/Audit20261023NeoToolsTextTimeToTextTests.cs`, описать отказ перехода в существующем `TimeToText.md`. Приёмка: большой Compact остаётся Compact с прежним текстом/временем и без события; после `Set(90f)` переход в Clock разрешён и даёт `01:30`, также без события изменения времени. Оценка: несколько часов, низкий риск; API и serialized fields сохраняются.

**P1, V1 — центральная компиляция и 31 невыполненная регрессия.** Владелец запуска — координатор; исправления обнаруженных ошибок принадлежат соответствующим сборкам. Выполнить после стабилизации исходников всех аудиторов. Точные файлы: `Assets/Neoxider/Tests/Edit/UI/Audit20261023NeoToolsTextSetTextTests.cs` и `Assets/Neoxider/Tests/Edit/UI/Audit20261023NeoToolsTextTimeToTextTests.cs`; затем существующие `SetTextTests.cs` и `TimeToTextTests.cs` в той же папке. Проверять реальный текст, состояние и историю событий; ошибка инфраструктуры или TMP-инициализации не считается успешной проверкой поведения.

**P2, V2 — неподтверждённый риск интеграции DOTween.** Проверить два подготовленных Play Mode сценария и один сценарий с отключённым `_onEnableAnim`: скрытая иерархия при включённой опции замораживает число, включение продолжает анимацию; уничтожение компонента прекращает записи в оставшийся TMP; отключённая опция разрешает анимацию скрытой цели. Проверить cleanup и восстановление `DOTween.defaultUpdateType`. Файлы при обнаруженном отклонении — только `SetText.cs` и его указанный регрессионный файл. Не менять поведение опции без воспроизводимого сбоя.

## P3: предложение общего C# API длительности

**Проблема.** Валидация, нормализация и выбор Clock/Compact остаются внутри MonoBehaviour; парсер принимает более широкий диапазон, чем отображение. Программисту без сцены приходится самостоятельно воспроизводить правила. Статический Clock-фасад насыщает чрезмерные значения, а компонент отклоняет их; это намеренно разные совместимые контракты.

**Reuse и дизайн.** Нового `TryFormatDuration`/`DurationFormatOptions` в текущих исходниках не найдено. Использовать существующие `TimeFormat`, `TimeDisplayMode`, `PrimitiveExtensions.FormatTime`, оба `TimeSpanExtensions.ToCompactString` и `TimeParsingExtensions.TryParseDuration`. Добавить обычный C# контракт в `Neo.Extensions`:

```csharp
public static bool TryFormatDuration(
    float seconds,
    DurationFormatOptions options,
    out float acceptedSeconds,
    out string formatted);
```

`DurationFormatOptions` — неизменяемая конфигурация без scene references: режим, формат, separator, разрешение отрицательных значений, показ нуля, выбор фиксированного Compact, включение секунд и число частей. Явный preset повторяет текущие defaults компонента. Успех возвращает нормализованное время и текст; скрытый ноль — успешный пустой текст. NaN/infinity/непредставимые значения возвращают `false`, `0f` и пустую строку. Конечный отрицательный ввод при запрете отрицательных значений нормализуется в ноль. Не добавлять singleton, интерфейс или второй строковый форматтер.

Сначала реализует и проверяет core владелец `Neo.Extensions`, затем Text использует его через уже существующую ссылку сборки. Обратной зависимости на TMP/Text/NoCode быть не должно. `Neo.NoCode` сохраняет существующие вызовы из `NoCodeBindText.cs` и `NoCodeFormattedText.cs`; менять их не требуется, владелец NoCode проверяет dispatch при интеграции. Чужие файлы этим планом не передаются владельцу Text.

Сохранить все serialized fields, методы, события, defaults, affixes и Clock-centiseconds. Старый статический `TimeToText.FormatTime` продолжает делегировать насыщение; новый Try API отклоняет неподдерживаемый ввод. При скрытом нуле компонент не добавляет affixes. Prefabs/scenes/ScriptableObjects, asmdefs и package configuration миграции не требуют. Новые файлы получают уникальные `.meta`; sample assets не создаются, активный `Samples~` не переименовывается, импортированный `Assets/Samples/NeoxiderTools/<version>/...` остаётся независимым.

Оценка: 1–2 дня плюс центральная проверка, средний риск отличий округления, знака, нулей и границ TimeSpan. Это предложение, не выполненная работа и не обязательное условие выпуска исправлений F1–F7/D1. Решение о включении API принимает координатор при чтении планов; рутина исправления D1 нового разрешения не требует.

## Порядок реализации, приёмка и остановка

1. Зафиксировать стабильный набор изменений `Neo.Extensions` и Text для центральной проверки; скомпилировать текущие исправления, отдельно от будущего API. Исправить воспроизведённые ошибки интеграции у их владельцев.
2. Добавить регрессию D1, внести минимальную атомарную проверку и выполнить затронутые тесты. Затем закрыть V1/V2: старые исправления не считать выполненными заново.
3. Если предложение включено в реализацию, сначала options/core и независимые EditMode тесты, затем адаптер TimeToText. Удалить дублирование валидации только после проверки эквивалентного результата.
4. Минимальная матрица core: все `TimeFormat` на репрезентативной дробной длительности; отрицательные/нулевые значения; Clock `2147483520f` принят и `2147483648f` отклонён; Compact `3000000000f` принят; непредставимый TimeSpan отклонён; фиксированные totals не переполняют Int32. Компонент сохраняет `[90, 120]` для вложенных событий и не публикует событие при смене только формата.
5. Обновить перечисленные английские docs, повторить scoped diff/UTF-8/API/serialization/GUID/link checks. Координатор проверяет пакет и зависимости в Unity 6.0–6.4 и отдельно 6.5+; текущая ветка компиляции не доказывает работоспособность другой. Новые распределённые `#if` не нужны; возможные ID-вызовы остаются за существующими централизованными compatibility helpers.

Готовность: обязательные компиляции успешны, затронутые EditMode и реальные Play Mode проверки подтверждают наблюдаемые результаты, нет новых относящихся к изменению ошибок Console или записей после уничтожения владельца. При сбое конкретного сценария остановить его приёмку, записать воспроизведение и владельца минимальной правки; не расширять архитектуру ради обхода. Пока процессы запрещены этой фазой, V1/V2 остаются открытыми. Независимую runtime QA, проверку Console и интеграцию с финальным состоянием соседних сборок статические проверки не заменяют.
