**P2, существенное улучшение — явный combat receiver в bridge; предложение.** Сейчас `RpgStatsDamageableBridge` принимает только serialized/parent `RpgCharacter`; чистый C# получатель требует дополнительного адаптера или сценовой структуры. Расширить существующий bridge, переиспользовав `Neo.Rpg.IRpgCombatReceiver` и `RpgDamageInfo` из `Assets/Neoxider/Scripts/Rpg/Interfaces/IRpgCombatReceiver.cs`. `RpgCharacter` уже реализует интерфейс; его explicit `TakeDamage` вызывает `DamageType`, поэтому отдельный damage engine не нужен.

```csharp
public void Initialize(IRpgCombatReceiver receiver);
public void ClearReceiver();
public bool TryTakeDamage(int amount, out float applied);
public bool TryHeal(int amount, out float applied);
```

Runtime override имеет приоритет над прежним `_character`/parent path и не сериализуется. `Initialize(null)` отклоняется явно; `ClearReceiver()` возвращает прежний путь. Уничтоженный Unity receiver возвращает false до явного clear/reinitialize, без скрытого перенаправления урона другому актору. Проверять Unity lifetime через объектную ссылку, не instance ID. Чистый C# receiver принадлежит вызывающему коду и не уничтожается bridge.

Старые void `TakeDamage(int)`/`Heal(int)` делегируют общей реализации ровно один раз; multiplier применяется один раз. Bool означает передачу положительного запроса живому объекту-получателю, не обязательное уменьшение HP; `applied` — синхронный ответ, допустим ноль при invulnerability, лимите или сетевой маршрутизации. Nonpositive amount и отсутствующий receiver дают false/0. Существующий default character path сохраняет `Damage`/`Heal` и authority routing.
