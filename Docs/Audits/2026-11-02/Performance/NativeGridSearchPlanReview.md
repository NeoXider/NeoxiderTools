## Why the reuse boundary is valid

Current public TryFindValidSwap initializes false/default outputs, obtains Generator, synchronously drains GetAllCells(false) in x/y/z order and GetNeighbors(cell) in configured direction order, applies live usability/reference gates, then invokes the private fresh-snapshot probe. CreateSnapshot copies GeneratedSize into existing private bool/int arrays; endpoint match checks touch only those arrays and the service's raw min length. The current O(P*B) repeated-copy/allocation term therefore has an existing reusable mechanism; one local snapshot reduces that term to O(B) for P>0 without rewriting neighbor enumeration or match rules.

FieldGenerator GetAllCells/GetNeighbors/GetCell and the relevant accessors are nonvirtual. GetAllCells' language yield is consumed by foreach, not a yield to Unity. Default GetNeighbors receives MovementRule.Directions; the constructor materializes it with new List<Vector3Int> and its setter is private. The optional arbitrary IEnumerable override is not passed by this query. Config/FieldCell state are direct fields; CanUseCell, snapshot operations and Vector3Int arithmetic invoke no payload predicate/event/virtual user hook. Shape predicates are not queried. The service query has no coroutine/event/RNG call between probes. Ordinary same-thread callers therefore cannot mutate/reenter through a supported query callback.

Exposed arrays/fields/direction contents remain mutable and unversioned. Existing per-probe copies already give no atomic/thread-safe result under unsynchronized concurrent writes. The plan correctly scopes reuse to one uninterrupted invocation and does not manufacture a mutation token, synchronization guarantee or cross-call cache. No thread-safety promise was found in the inspected module contract. If the final diff uncovers a new supported callback path, this conclusion must be reopened rather than silently extending reuse.
