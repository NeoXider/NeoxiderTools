## Final dependency API for Draw / Demo

- `SpawnUtility.RetirePool(GameObject source) : bool`: use this unified API before destroying an exclusively owned automatic source. Retires exact manager and fallback registrations, blocks later unified Spawn for that source, preserves every storage root. True means at least one registration was removed; even an unused source is marked retired for unified routing. A managed reference to an already-destroyed source may still remove its registration. Null is a no-op. No name lookup/deletion or reference-count framework.
- `PoolManager.RetirePool(GameObject source) : bool`: exact manager registration only; no singleton creation/search. Marks the source retired in the current manager, removes its registration before retiring the pool. Missing current manager returns false. Use SpawnUtility's API when routing can change.
- `NeoObjectPool.IsRetired`, `NeoObjectPool.Retire()`: idempotent terminal retirement. Clear only inactive entries; outstanding rentals remain valid and are destroyed on valid return. GetObject returns null after retirement. Late-return IPoolable and Mirror callbacks keep their existing order/context.
- `PooledObjectInfo.TryRegisterReleaseCleanup(NeoObjectPool expectedOwner, int expectedGeneration, System.Action<GameObject> cleanup) : bool`: one pending hook for exactly the outstanding owner/generation. Register after acquisition/material creation. A second pending registration, wrong owner, stale generation or already-returned/destroyed object returns false; null cleanup throws ArgumentNullException. Hook detaches before invocation and runs after existing IPoolable/Mirror release callbacks, before storage/eviction/reuse; external destruction also consumes it once. It does not use cached IPoolable discovery. On return/destruction cleanup sees IsInPool=true, so it must not use an active-rental predicate to skip its own exact resource disposal. As with existing lifecycle callbacks it must not throw or return/re-rent its transitioning instance.

Draw owns capture/check of owner+generation before all renderer/material/geometry mutations, exact material restoration/freeing inside the hook, local disposed-record guards, and retirement only for its unique auto source. Demo owns replacing Survivor's name-root disposal with exact source identities and this API after its own rental returns. Assigned/shared sources must never be retired by these consumers.

Weak retirement markers do not retain destroyed automatic source keys; no storage-root ownership is inferred. Shared containers intentionally remain. No shared asmdef, tracker or other owner's source was changed.

The exact-source APIs also reach a pool during its first prewarm callback. Successful callback retirement returns true, stops further warmup, and cancels the outer Get/Spawn with null; a later duplicate startup entry cannot recreate it. Prewarm instances already acquired complete the normal transition and receive a destructive return. No callback returns or re-rents its own transitioning instance. Direct public construction remains synchronous with its existing signature and callback order.

## Compatibility and deliberate behavior

Existing Get/Return/Clear signatures, serialized names, prefabs and ordinary callback order are retained. Retirement is additive and terminal: only callers explicitly retiring an exclusively owned source opt into null future retrieval and destructive late return. Different same-named source identities keep working. Clear remains reusable/inactive-only. There is no inferred root ownership, generic shared-source reference counting or deletion of an empty shared container.

11.0 callback reentry behavior is intentional: after Stop/restart/Clear/disable invalidates an active producer, that producer's remaining event/RPC tail is suppressed; it cannot update the replacement session. Already-created objects stay tracked. Normal synchronous calls outside invalidation keep their paths. Lifecycle callbacks and the new cleanup hook remain nonthrowing and must not return/re-rent their own transitioning instance; no arbitrary callback rollback framework was introduced.
