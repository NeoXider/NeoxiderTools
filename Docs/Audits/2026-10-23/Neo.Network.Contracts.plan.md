## Уже выполнено

Созданы `Assets/Neoxider/Docs/Network/Contracts.md` и `Assets/Neoxider/Tests/Edit/Network/Audit20261023NeoNetworkContractsTests.cs`: семь случаев чтения/записи старых JSON-значений и выбора `None` при отсутствующем поле. Это завершённые изменения, а не будущие задачи. Статически проверены UTF-8, XML, ссылки, GUID, декларации и whitespace. Unity-компиляция, генерация XML компилятором и NUnit не выполнялись ни в аудите, ни при планировании.

## Существенное улучшение: независимый вычислитель политики

**Предложение, не реализация.** Разработчику нужен единый проверяемый контракт авторизации без Mirror/GameObject-зависимостей. Сегодня enum независим, а его проверка находится только в транспортном адаптере. Извлечение полезно отдельно от минимального исправления NC-03; его можно отложить, сохранив исправленный адаптер.

Повторно использовать существующие `NetworkAuthorityMode` и `NeoNetworkState.IsAuthorized`; новый менеджер, компонент, NoCode-мост или сторонняя зависимость не нужны. Изучен `neoxider-tools/references/network.md`. Существующий `IsLocalHostConnection` классифицирует тип соединения, поэтому при делегировании сохранить точное действующее сравнение `sender == NetworkServer.localConnection`, не подменять семантику классификатором.

Новый pure C# API в namespace `Neo.Network`:

```csharp
public static class NetworkAuthorityPolicy
{
    public static bool IsKnown(NetworkAuthorityMode mode);
    public static bool IsAuthorized(NetworkAuthorityMode mode,
        bool isDirectServerCall, bool isLocalHostSender, bool senderOwnsObject);
}
```

Это эскиз сигнатур. Неизвестное значение отклоняется до любых исключений для server/host. Для известных значений: `None` разрешает любой вызов; `OwnerOnly` — server, local host или владельца; `ServerOnly` — server/local host. Факты формирует доверенный адаптер: прямой вызов соответствует `sender == null`, владение — существующему сравнению `identity.connectionToClient`. Игра продолжает использовать существующий локальный/offline flow.

Точные будущие файлы и владельцы:

- `Assets/Neoxider/Scripts/NetworkContracts/NetworkAuthorityPolicy.cs` и уникальный `.meta` — Contracts; без Unity/Mirror API и новых assembly references.
- `Assets/Neoxider/Tests/Edit/Network/Audit20261023NeoNetworkContractsAuthorityPolicyTests.cs` и `.meta` — новые тесты pure API; существующие семь serialization-кейсов сохраняются.
- `Assets/Neoxider/Scripts/Network/Core/NeoNetworkState.cs` — `Neo.Network`: сохранить публичную сигнатуру, делегировать вычисление после получения фактов.
- `Assets/Neoxider/Tests/Edit/Network/Audit20261023NeoNetworkAuthorityAdapterTests.cs` и `.meta` — `Neo.Network`: минимальные регрессии адаптера, вначале для исправления NC-03, затем для делегирования. Перед созданием проверить отсутствие совпадающего имени.
- `Assets/Neoxider/Docs/Network/Contracts.md` — Contracts: публичный C# пример и таблица решений; `Assets/Neoxider/Docs/Network/README.md` — сетевой владелец: ссылка и описание поведения некорректной политики.

Сохранить `None=0`, `OwnerOnly=1`, `ServerOnly=2`, getter интерфейса, serialized fields потребителей и host-исключение. Отказ для некорректных чисел — намеренное изменение поведения; описать при выпуске, не заменять их молча на `None`. Префабы, сцены, ScriptableObjects и sample layout менять не требуется; текущий `Samples~` сохраняется. Inspector/NoCode продолжает выбирать enum в существующих компонентах, вызывающих typed API; дополнительный authoring-слой не нужен.

Оценка: половина–один рабочий день плюс централизованная проверка. Основной риск — изменение host/owner-семантики при переносе или неожиданное наличие некорректной конфигурации. Изменение привилегий host либо значения политики по умолчанию относится к отдельному продуктовому решению и этим планом не предлагается.

## Последовательность и приёмка

1. `Neo.Network` сначала исправляет NC-03 с регрессией, не ожидая нового API. Проверить `-1`, `3`, `int.MaxValue`; результат false для remote, owner, server и local host. Для именованных значений проверить remote не-владельца/владельца, server, host, null target и объект без identity. Server/host по известным политикам сохраняют допуск, включая чужой объект; remote owner не получает `ServerOnly`.
2. Централизованно закрыть текущий compile/EditMode-долг. При включении улучшения сначала добавить pure API и тесты таблицы решений, затем подключить единственный существующий транспортный адаптер и повторить его проверки. Editor-активацию не переносить в вычислитель авторизации.
3. Обновить указанные публичные страницы после итогового API: C# вызовы, Inspector-политики, server/host-исключения, обработка некорректных чисел. Сохранить XML-разделение сборок.
4. Координатор проверяет Unity 6.0–6.4 и 6.5+ с Mirror; без Mirror — Contracts и минимального клиента в отдельном доступном окружении. `Neo.Editor.Tests.asmdef` сейчас явно ссылается на Mirror: отсутствие Mirror в новом тестовом исходнике не доказывает независимость всей тестовой сборки. Новые настройки/установки данным планом не требуются. В pure API нет Unity-version веток; ветви транспортных зависимостей проверяются соответствующей компиляцией, общие compatibility gates сохраняются.
5. EditMode покрывает serialization, evaluator и адаптер. Узкий PlayMode smoke для сценового контракта нужен при проверке NC-02/изменении адаптеров, без создания sample-сцен: наблюдать `activeSelf`/`activeInHierarchy`, включая inactive parent. Полный игровой PlayMode-прогон для деклараций не требуется. Перед выпуском проверить `.meta`, UTF-8, scoped diff, отсутствие циклических ссылок и сохранение UPM sample paths.

Работу считать проверенной только после реальных центральных compile/test receipts; статический анализ не заменяет их. Неисправности чужих сборок маршрутизировать владельцам, не исправлять скрытно. Новое API остаётся предложением до включения в общий порядок реализации; минимальное исправление и проверка уже выполненного аудита от него независимы.
