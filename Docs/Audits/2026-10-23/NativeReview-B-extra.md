## Independent interaction verdict

**Approve the minimal design direction:** a lazily populated shared raw-hit backend reached through the existing `InteractionRayProvider`/internal helpers can remove N identical camera physics queries. A mandatory new controller, target registry, scene component or scene wiring is unnecessary for that correction. Each existing target can evaluate its own rules against the same complete raw results and retain its current input/events. No required member needs to be added to `IInteractiveTarget`.

**Do not approve a frameCount-only implementation or a global chosen-target result.** The safe sharing unit is the exact physics request within an explicitly stable epoch. Live target evaluation, complete hits and a declared invalidation/fresh-query contract are required. Universal parity with arbitrary unannounced physics mutations interleaved between MonoBehaviour Updates cannot be promised by a transparent cache; there is no world revision in these current call sites. This limitation must be explicit, rather than hidden behind “one immutable snapshot per frame.”

Original owner: Neo.Tools.InteractableObject / `neo-audit-1023-b07-03`; Core query contracts are read-only dependencies. The newer interaction-design document supersedes the plan's mandatory controller/registry prerequisite and its overbroad policy-key requirements. Superset-mask merging and longer-ray reuse are optional later optimizations, not part of the minimum repair.

### Exact key and 2D trigger contract

One internal raw-query key needs the actual world/scene used, dimension and query kind, unrounded origin/direction, exact maximum distance, physical mask and effective query filter/global settings. Current static Physics/Physics2D calls address their default physics worlds; selecting the camera GameObject's local physics scene instead would change behavior. Any future explicit-scene overload must supply that actual scene in the key.

Use component-wise exact float equality/hash, not Unity Vector3 operator== with its approximate comparison. Validate geometry before querying. Keep camera/source partitions required by the design, viewport/projection/input context sufficient to generate the correct ray, and distinct Mouse/Center contexts; hover/click with the same source geometry/policy can reuse. A forClick/target ID alone is not a physical difference. Distinct camera contexts remain distinct even when a particular frame's geometry happens to coincide.

The important current distinctions are:

- 3D mouse/look uses explicit QueryTriggerInteraction.Collide or Ignore. That value belongs in the raw key; Physics.queriesHitTriggers is not an extra restriction on an explicit value. If a backend supports UseGlobal, resolve/key its effective global value. Other applicable engine globals, such as backface policy, must not be frozen across an epoch change.
- 2D mouse intersection and keyboard planar queries use legacy/global filtering. Capture effective Physics2D.queriesHitTriggers, and applicable start-inside/global query policy; keep intersection and planar-ray kinds distinct. Per-target includeTriggerCollidersInMouseRaycast/includeTriggerCollidersInLookRay is only a postfilter here, so targets differing only in that checkbox share the raw request. Global false + local true still cannot hit a trigger; changing global false→true within the pass must produce a new context/epoch. Never toggle the global flag temporarily to implement a target's setting.
- 2D range LOS uses explicit ContactFilter2D.useTriggers and its enabled mask/depth/other filter fields. Preserve the exact overload/filter semantics; do not replace it with a legacy overload or silently AND its explicit trigger choice with a global default. Only globals the selected API actually consults belong in its effective key. Their Unity-version behavior remains an execution/compatibility case, not a claimed run here.
- obstacleLayers is a physical mask for range LOS, not a new mask for mouse/keyboard targeting. Mouse/look keep `~0`, including its difference from Physics.DefaultRaycastLayers. No all-layers superset replacement for a genuinely masked query in the minimum correction.
- Target identity, explicit collider, nested binding, checkObstacles, foreign-trigger blocking, ignored hierarchy, tags/eligibility and range rules stay out of the raw key unless they actually change a native parameter. Putting each target/rig exclusion in the raw key recreates N groups. InteractiveObject has no new tag filter to introduce; PhysicsEvents2D/3D callback masks/tags are a separate channel.

For keyboard unlimited range or the 2D direction fallback, target-dependent length/direction is a real different key. For range-to-center versus range-to-hit-point, do not assume equality. LOS may remain O(N); preserve it and report it separately from shared camera query counts.

### Completeness, ownership and lifetime

The three 16-element target arrays (`InteractiveObject.cs:162–164`) are not a completeness guarantee. Both raw arrays and target-specific candidate storage must support all hits; merely sharing a 16-hit truncation is not a correct repair.

Minimum practical backend: one NonAlloc query for a new context, and on saturation one equivalent full fallback where available, then retain/grow reusable context buffers. For 3D, equivalent RaycastAll must keep length/mask/trigger mode; 2D intersection/planar fallback must keep their respective global/filter semantics. Explicit ContactFilter2D LOS needs an equivalent full/list route, not a global-filter shortcut. If an API cannot prove completeness at a hard limit, return an explicit incomplete outcome and do not accept unsafe target/LOS decisions. Count actual native calls, including fallback. Cold saturation is separate from one warmed request per context. Do not run fallback per subscriber.

Each live key owns its buffer. Consumers borrow read-only hits only for the declared epoch and consume them before callbacks; do not expose mutable arrays, sort them, cache target decisions in them or retain a borrowed view in target state. A query for a different key must not overwrite the first key's buffer. Reuse slots between epochs; release old camera/collider references and bound retained buffers rather than retain every historical moving-ray key forever. Domain reset must clear state. A camera key must use retained identity or the shared StableId gateway, never a new scattered obsolete Unity-ID call.

A lazy automatic interaction epoch may begin on the first query of the frame and expire with the next frame, plus explicit world invalidation. It requires no new target registry. Current target disable clears local hover/press state (`OnDisable/ResetInputState:277–295`); keep that local ownership and live isActiveAndEnabled/interactable checks. Target availability alone need not rerun physics if geometry did not change; never share accepted hover/click/up state across consumers.

Recommended additive C# escape hatches are a public `InteractionRayProvider.InvalidateQueries()` (global epoch increment is sufficient initially) and a fresh-query mode/internal entry point usable by external synchronous APIs and manual simulation. Names are proposals, not new declarations. Existing public IsInInteractionRange should request fresh evaluation by default outside the automatic interaction pass. Time.frameCount alone cannot distinguish multiple manual simulation steps.

**Existing callback parity requires special treatment.** A hover/range/down/up/click callback can move/disable a blocker or call Physics.SyncTransforms, then reenter an interaction query. A later target currently queries the changed world. A raw frame cache would otherwise reuse pre-callback hit distances/membership. Recommended minimum: invalidate at entry and exit/finally of interaction-owned external callback dispatch; callback reentrant queries use a fresh/bypass path. Do not queue all existing UnityEvents to a later controller phase just to keep the counter at one; that changes observable timing. Callback/world-change revisions legitimately add native queries and must be counted separately. An arbitrary unrelated script's unannounced mid-frame world mutation still requires the explicit invalidation/fresh contract; do not claim automatic detection. Camera/ray/filter changes naturally change exact keys, while a world mutation with the same ray does not.

This is conditional approval of a stable-epoch raw cache, not proof that every possible Update interleaving is indistinguishable. The coordinator must record this temporal contract before implementation; the geometry/settings/event mechanics remain unchanged.

### Interaction parity cases for later execution

1. 1/100/1000 enabled targets, same source/raw settings, stable world after warmup: one 3D camera query per context/epoch. Target-only postfilters do not multiply it. Check actual raw calls plus target state/events; separately count unique LOS and EventSystem raycasters.
2. Mouse, Center and Both; pointer at/off center and outside pixelRect; two split-screen cameras/render targets; missing/disabled provider/camera; per-target center override. Preserve actual hit points, hover/click distinction and no duplicate click/up.
3. 2D global trigger true/false × local include true/false for both mouse intersection and keyboard planar queries. Global false/local true remains excluded; local false narrows the true-global result. A global switch in the same frame refreshes raw membership.
4. Explicit 2D obstacle ContactFilter trigger true/false under both global values, plus two obstacle masks. Compare each route with an uncached complete request using the same overload; do not infer 2D semantics from 3D.
5. Wall before target, foreign trigger before target, checkObstacles on/off, ignored rig hierarchy on/off, explicit sibling collider, nested targets, equal-distance target/blocker. Multiple eligible targets with checkObstacles=false remain possible.
6. At least 17/64/1000 hits with target/blocker beyond the original capacity, arbitrary creation order and ignored hits. Both raw and candidate evaluation are complete; warmed fallback is not repeated per target. Preserve existing equal-distance comparison; native tie ordering/point selection must be declared rather than silently replaced with a new sort policy.
7. Distinct per-target LOS/checkpoints/lengths, 3D-vs-2D, finite-vs-unlimited keyboard length and 2D Z-forward fallback. No false deduplication. Equal actual LOS contexts may share; do not remove range events to meet a camera-query budget.
8. Callback moves/disables a blocker, reenters the query, disables/pools the target or changes camera/mode/mask. New revision reflects the changed world and old borrowed buffers are not overwritten while read. Manual simulation followed by Invalidate/fresh sees new hits; no stale target registration exists to clean up.

## Independent RPG verdict: bounded catch-up is mandatory

Original owner Neo.Rpg / `neo-audit-1023-b05-03`. Native C C-28 is independently confirmed. `RpgCharacterResourceService.TickRegen:244–254` adds delta to a public float TickAccumulator and subtracts tickInterval without a finite/progress/work bound. `RpgEffectShelf.Tick:273–292` does the same in a private float map, calling damage each iteration. +Infinity never decreases; huge finite float.MaxValue with interval0.5 also cannot decrease under float subtraction. Promoting that huge total to double alone still cannot make subtracting0.5 progress at its magnitude. A finite guard by itself therefore does not close the defect.

**Recommended policy:** at most **1024 delivered logical ticks per entry per public Tick/TickRegen invocation**; discard excess whole-interval backlog and retain the fractional remainder. RpgCharacter.Update:216–218 calls each once per Update, so this is 1024/entry/update for the ordinary driver. It is not a global character/frame CPU budget and cannot bound arbitrary caller loops or recursive subscriber code. No new required scene clock/controller or simulation-state framework is needed.

Dropping excess whole intervals is deliberate overload behavior to document for 11.0.0. Keeping float.MaxValue of deferred debt would replay maximum work for an effectively unbounded number of frames and could damage/regenerate after the original stall or pause. The chosen recommendation avoids that debt while leaving all calls with <=1024 due ticks unchanged in logical cadence. Do not silently aggregate 1024 callbacks into one large mutation: each tick can clamp, change stacks/rate, trigger death/removal or publish events.

### Minimum numeric implementation contract

- Reject nonfinite/nonpositive delta for regen advancement before changing pause/accumulator/resources. Shelf must skip status time accumulation/damage for such delta but still perform its existing UTC expiry processing; an early return from the whole Shelf.Tick would change paused expiration behavior.
- Validate effective interval after the existing normalization: regen finite intervals retain its minimum0.01; status retains the current nonpositive→1-second fallback and positive authored small intervals. Do not impose the regen minimum on status ticks. An effective NaN/Infinity interval cannot enter the drain loop.
- Use double working arithmetic and private accumulator storage where possible; keep public signatures, particularly `RpgResourceRuntime.TickAccumulator:31` as float. Changing that property type to double would break public API. A private/internal double backing clock is an optional narrow implementation detail if needed, not a serialized migration.
- Compute a bounded number of due ticks before any unbounded iteration; clamp before conversion to int. Use a counted for loop and/or an explicit decreasing-value guard. Never rely exclusively on `remaining -= interval` terminating.
- Compute the fractional remainder without subtracting trillions of intervals. For very disparate finite magnitudes, `(double)accumulator + delta` can lose the old small fraction; if the contract promises to retain it, combine separately computed modulo contributions before normalization. Example accumulator0.25, delta float.MaxValue, interval0.5 must retain0.25 under the recommended policy. Preserve a finite negative externally assigned accumulator's existing delayed-phase behavior rather than silently clamping every negative value to zero; invalid NaN/Infinity storage may be repaired to zero on a valid advancement under an explicit corruption policy.
- After the cap, discard all remaining complete intervals, not the fractional portion and not the entire clock. Persist a finite remainder in the promised range. Float storage can round a value just below an interval up to that interval; handle/test that projection explicitly or retain an internal double remainder behind the unchanged float API. Do not hide a nearly full-interval loss behind “reset to zero.”
- Validate the rate and widened per-tick amount before conversion/dispatch; no NaN/Infinity payload or poisoned resource clock. Unsupported numeric definitions contribute no invalid mutation/event. Preserve current zero/negative-rate behavior: tick regen can consume cadence without Increase, while the status condition currently skips accumulation when damage rate is nonpositive. Do not invent a new rate/clamp policy for ordinary representable values.
- Retain the mutation/identity fences required by Native C C-27 after external setters/resolvers/notifications. A callback can Build/Clear resources or remove/refresh a status; never write an old remainder into replacement state or continue stale entries. Keep status accumulator consumption before its callback and do not overwrite callback-owned replacement clocks afterward. Protect a claimed per-entry budget from nested Tick reentry, with a minimal guard/finally or shared invocation budget; a recursive call must not obtain endlessly renewed 1024-tick budgets.

A small internal arithmetic helper may centralize the budget/remainder policy, but it must not own gameplay callbacks or replace the two services. No per-tick allocation, global logging loop or new public serialized setting is required. A fixed internal constant is sufficient for this correction; future configurable/global budgets are separate proposals.

### Cadence, pause and lifecycle that must remain

`TickRegen:217–229` checks definition/alive/full gates before pause. When a positive pause exists, it subtracts the entire valid delta and continues without applying leftover time or advancing TickAccumulator. Preserve that crossing behavior: pause0.25 + delta0.5 performs no regen this call; next valid delta advances normally. Dead/full gates currently also stop that resource's clock/pause advancement. Reordering them would be a separate gameplay change.

`RpgEffectShelf.Tick:246–305` uses DateTime.UtcNow via `RpgTimeUtility` in `RpgActiveEffectEntries.cs:8–12` for lifetime, independently of scaled delta. Buff expiry comes first; each status's due damage precedes its expiry notification. Keep that order, including valid small-step behavior when the status has expired by UTC. Do not make pause freeze expiration or introduce a new clock mode in this bounded fix. Removing/clearing/restoring status entries clears the private accumulator; refreshing an existing status currently retains it. Preserve these rules and existing mutation-version exits.

1024 × entries can still be expensive and each callback is arbitrary application code. This is a termination/safety bound, not an FPS guarantee. Any aggregate budget/fairness or continuous fast-forward design needs separate profiling and compatibility decisions after the minimal fix.

### RPG acceptance cases for later execution

1. Never execute the known infinite recipe on unfixed code. After repair, NaN/±Infinity delta returns bounded with no regen/status-damage mutation or invalid payload; valid existing fractional clocks survive. Shelf still expires an intentionally old UTC entry once.
2. Interval0.5, total2.75: five exact ticks, remainder0.25; next delta0.25 gives one tick. Check actual Current/events or damage payload/count, not a copied arithmetic helper alone.
3. Interval1, total1026.75: exactly1024 ticks, remainder0.75, two skipped whole intervals never reappear; next delta0.25 gives one ordinary tick. A zero/paused delta does not drain deferred work.
4. Huge finite delta and huge finite preloaded resource accumulator; positive tiny status interval; finite operands whose float addition would overflow. Every call terminates, dispatch count <=1024/entry, stored clock/payload finite. Include0.25 + float.MaxValue with interval0.5 to observe fractional preservation.
5. Effective interval NaN/Infinity, nonfinite rate and widened amount outside float range do not enter an infinite drain or publish invalid damage. Existing finite zero/negative/default interval policies and normal small status cadence remain unchanged.
6. Pause crossing, alive/full gates and per-second regen preserve current normal behavior. Validate fractional phase over many ordinary binary-exact steps and near a representable tick boundary; double precision is not a substitute for those observations.
7. First callback removes/refreshes a status, clears the shelf, replaces resources or reenters Tick; no stale mutation/remainder write or renewed unbounded budget. Exceptions release any new ticking guard in finally; the next independent call still works.
8. Multiple entries each receive their declared per-entry allowance without starvation from a previous entry's large step. Status normal damage/expiry order, paused UTC expiry, refresh remainder retention and clear/restore reset match current contracts. The tests need not replace the wall-clock architecture to verify the bounded correction.

## Handoff decision and remaining evidence

Recommended for original-owner implementation after root authorization: exact-context lazy raw-hit cache with complete buffers, target-local evaluation and explicit epoch/freshness boundaries; bounded1024-tick RPG catch-up with excess whole debt dropped and fractional phase retained. Reject mandatory interaction controller/registry as a prerequisite, approximate/grouped masks or global selected-target state, IsFinite-only RPG guards, and public float→double API changes.

The callback/world epoch contract and deliberately lossy overload policy must be recorded by the coordinator before declaring compatibility. All parity/numeric cases above remain unexecuted; exact native overload/global-flag behavior, buffer completeness, callback timing and both supported Unity compile branches require central evidence after every source writer finishes.
