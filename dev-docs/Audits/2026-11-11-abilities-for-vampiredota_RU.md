# Аудит Neo.Abilities для VampireDota (2026-11-11)

Проверено по коду пакета 12.1.0 (`Scripts/Abilities`, ядро `Neo.Abilities.Fixed`) и по дизайну
VampireDota [CultivationRealmsV2](../../../VampireDota/Docs/Features/CultivationRealmsV2.md). Unity и тесты при
аудите не запускались; номера строк — на коммите `b8d607d9`.

**Итог.** Целочисленное ядро `Neo.Abilities.Fixed` подходит для детерминированной симуляции: в нём нет float,
заявленные горячие пути без аллокаций, есть тесты соответствия с float-ядром. Для культивации ему не хватает
таймлайна каста и канала, мультипликативной шкалы силы и тегов юнитов и способностей. Поэтому VD в бою его пока
не использует: из ядра в проде работает только `FixedMath` (`StatBlock` → `RationalStat`), касты идут через
собственный `AbilityExecutor` (`DomainMatchSimulation.cs:265`), а `AbilityCastHost` гоняет ядро лишь как
диспетчер эффектов: цена и откат обнулены, мир пустой, кэш на 256 вариантов с полной пересборкой.

## 3. Удобство и API

- F13 (средняя): все id строковые, VD вызывает `def.Id.ToString(...)`. Контекст эффекта не знает экземпляр модификатора, у `modifier_removed` нет `InstanceId`. Нужны `SourceModifier` в контексте и `InstanceId` в событии.
- F14 (средняя): у ядра нет билдеров и шаблонов, `FixedEffectNode` — около 25 изменяемых полей. Нужны fluent-билдеры и fixed-шаблоны.
- F15 (средняя): у шкалы эффекта нет `Denominator` (у вклада в свойство есть), точные дроби VD округляются к Q8.8.
- F16 (средняя): Ability Designer не показывает отчёт конвертации в fixed и предлагает `knockback/pull/teleport`, которых в ядре нет.
- F17 (низкая): фраза «allocate nothing after warm-up» в `FixedCore.md:171` неверна для новых модификаторов.

## 4. Детерминизм

- F18 (средняя): хеш состояния (`FixedAbilitySystem.Hashing.cs:52-65`) не включает позицию, базовые свойства, прочие пулы, постоянные состояния, аккумуляторы, `ReadyAtTick` реакций и счётчики id — рассинхрон замечается поздно.
- F19 (низкая): `char.ToUpperInvariant` для не-ASCII id зависит от таблиц рантайма (`FixedIds.cs:73`). Нужно запретить не-ASCII id валидатором.
- F20 (низкая): `GetSlots` отдаёт порядок словаря, зависящий от истории grant/revoke (`FixedAbilitySystem.cs:261-271`).
- Float-ядро для lockstep не годится по дизайну: юниты тикают в порядке словаря (`AbilitySystem.cs:916-927`).

Проверено и в порядке: в Fixed нет float, Unity Random и Time; сортировка целей тотальна (дистанция, затем id);
шина событий без аллокаций, со снимками на каждом уровне вложенности.

## 5. Что сделать для VampireDota в первую очередь

1. Таймлайн каста и канал с прерываниями (F1, F2): снимают прорыв, взлёт, круги и собственный `AbilityRuntime`.
2. Мультипликативная шкала силы (F3, F15): убирает `TechniquePower` и кэш на 256 вариантов.
3. Теги юнитов и способностей (F4): заменяют `AbilityTargetRules`, дают склонности и воздушные цели.
4. Целые id, пул экземпляров, полный хеш (F9–F11, F18): условие фазы 5 с ордой.
5. Группы откатов, `ResourceBelow`, длительность призыва (F5–F7).

## 6. Survivor-демо: что собрать из модулей

Что демо пишет само, хотя в пакете уже есть:
- автокаст и поиск ближайшего (`SurvivorPlayerController.AutoCast`, `SurvivorGame.FindNearestEnemy`) — `AbilityAutoCaster` и пространственный запрос;
- опыт и уровни (`SurvivorGame.AddXp`) — `Core/Level/Components/LevelComponent`;
- камера — `Tools/Move/Follow` (`TwoD`, `AxisLimit`); таймер — `Tools/Time/Timer` и `TimerTextFormatter`;
- полосы HUD — `AbilityUnitBehaviour.HealthNormalized` с NoCode `SetProgress`;
- контактный урон — шаблоны зон `Aura` и `FormationZone`.

Чего не хватает модулям пакета:
- `Spawner.cs:393-410,682-697`: выбор префаба равновероятный, нет весов, времени открытия, нарастания и спавна кольцом вокруг цели (нужны SpawnTable и режим AroundTarget);
- `NpcFollowTargetCore.cs:8-12`: преследование только через NavMeshAgent (нужен кинематический seek с `move_speed` и stun/root);
- `MagneticField.cs:102-130`: притяжение только для 3D Rigidbody (нужны кинематическое притяжение и событие сбора);
- нет драфта апгрейдов «N карточек из пула» с лимитом взятий (кандидат — UpgradeDraft в Progression);
- `LevelCurveDefinition` продублирован в `Core/Level/Data` и `Progression/Data`;
- `AbilityCooldownSource` привязан к одному id способности, нужен источник по индексу слота;
- нет моста «контроллер движения ← `move_speed` / rooted».

Допущения 2D и 3D:
- `AbilityProjectileBehaviour.cs:115` и `AbilitySystemBehaviour.cs:313` поворачивают снаряд через `LookRotation`: в XY-сцене спрайт, вероятно, встаёт ребром к камере (у `AbilityZoneView` выбор плоскости есть, у снарядов нет; глазами не проверено);
- `AbilitySpatialGrid.cs:297` считает сферическое расстояние, в 3D в радиус входит высота;
- само демо жёстко в плоскости XY (`SurvivorGame.cs:338,391,710`).
