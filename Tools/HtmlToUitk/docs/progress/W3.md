## Interface notes for W2 and root (W3 view)

1. Rules public API: `RuleEngine.CreateDefault(IRuleCatalog catalog = null, IFileSystem fs = null, IStringTables tables = null)` implements `IRuleEngine` and also exposes `Detect(AnalysisInput)` and `Plan(AnalysisInput, constructs)`; `ConstructDetectors.Default()` returns the three detectors (selectors, at-rules, declarations); `new TierPlanner()`; `RuleCatalog.Embedded` / `RuleCatalog.Load(json)` (also `EmulatedSeverity(id)`); `ConfigStringTables(fs, baseDirectory)` loads the string tables so Rules can report L003/L004; `fs` is needed for D012 (missing image file).
2. Rules is the single source of truth for validation diagnostics: it reports the Info/Warning of every ConvertTime/Runtime construct (C001 ... C022, P011) and it PREDICTS the emulation failures it can see statically (E001: unresolvable grid templates, transform functions in the wrong order). For those constructs the planner returns Reject (no EmulationId), so the emulation must not run and must not report E001 again. Convert reports only what is knowable at transform time: Load stage J002 J003 J006 J007 J009 J010, J011, J012, approximation warnings (Severity Warning, EmulationId set) and E001 that Rules could not predict. Rules owns J001, J005, J008, and exposes no J004 (needs the assemble mode): W2 reports J004 in singleDocument.
3. A decision with `RuleId == null` is silent (shorthand-expand, animation declarations, invalid keyframes whose errors come from A-rules); `Tier.Reject` with `EmulationId == null` means do not emulate.
4. `TierDecision.EmulationId` values: grid-flatten, gap-margins, static-selectors, pseudo-elements, calc-fold, viewport-units, relative-units, media-breakpoints, keyframes-animator, gradient-bake, shadow-bake, filter-bake, backdrop-blur, overflow-scrollview, fixed-to-root, z-order, transform-decompose, shorthand-expand. Construct keys are in `ConstructKeys` (for example `display:grid`, `prop:gap`, `pseudo:not`, `pseudo-element:before`, `fn:calc`, `unit:vw`, `at:media`, `at:keyframes`, `anim:declaration`).
5. Open point for root: exit codes. docs/ARCHITECTURE.md 6.3 says 0 pass, 1 FAIL (or warnings with --strict), 2 usage or I/O error; the task text lists 0/1/2/3 differently. The CLI follows the document. (Superseded by the HANDOFF below: 0 PASS, 1 FAIL or warnings with --strict, 2 usage/IO. Also J001 is reported by the Core StyleEngine, not by Rules.)

- Exit codes: 0 PASS, 1 FAIL (or PASS WITH WARNINGS with --strict), 2 usage or I/O error (latest root instruction; ARCHITECTURE 6.3 agrees; an earlier message listed 0/1/2/3 and is superseded). `ExitCodes` in Rules encodes it: Pass 0, Fail 1, Warnings 1, Usage 2.
- Contracts are frozen. `CapabilityMatrix`, `PropertyCapability`, `Animatable` live in Contracts; `RuleInfo` has no emulated severity: use `RuleCatalog.EmulatedSeverity(id)`. PropertyCapability has no value type or layout flag: those come from spec/uss.json (`UssSpec`).
- spec/rules.json, uss.json, dialect.json and capabilities.*.json are linked into the Rules and Model assemblies as embedded resources: rebuild after a spec change. `spec/schemas/capabilities.schema.json` is root-owned: reader output must keep validating against it (property entries may only have id, inherited, animatable, values, evidence).
- Rules is the single source of truth for validation diagnostics of emulatable constructs: Info or Warning for ConvertTime and Runtime constructs, and static prediction of E001 (unresolvable grid templates, transform functions out of order) as Tier.Reject with no EmulationId so the emulation does not run twice. A decision with `RuleId == null` is silent. Convert reports only what it learns at transform time.
- Core StyleEngine already reports C033 and J001 into the sink: Rules must NOT report them again. Known issue (S08 skipped): StyleEngine reports J001 for custom properties that a skin and the page both define; the fixture expects C034 only.
- Severity policy lives in `RuleReporter.ReportDecision`: Reject uses the catalogue severity; ConvertTime or Runtime uses `emulatedSeverity` (Warning when the construct is marked approximate, for example gap with wrap); Native uses `emulatedSeverity` and is raised to Warning for assembly-only functions (linear-gradient) and for box-shadow written as drop-shadow.
- A pseudo-element whose `content` is text with letters becomes L001 (Reject) instead of C005; invalid keyframes (layout or non-animatable properties) suppress their C007 because A002 or A003 report them.
- Bash tool trap: heredocs with backslashes or triple single quotes break; write files with the Write tool and apply edits with a small `python -I <file>.py`. NUnit 4 has no `StringAssert` (use `Assert.That(x, Does.Contain(...))`).
