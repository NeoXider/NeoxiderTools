# Tests-Play-Network — индивидуальный план реализации

Дата: 2026-10-23. Продолжение исходной сессии аудитора, `gpt-6.1-sol`, `max`. Основание: [аудит](Tests-Play-Network.md), [контракт планирования](PLAN-CONTRACT.md), supplemental-запись manifest. Эта фаза изменяет только данный план.

## Текущее состояние

Добавлены `Assets/Neoxider/Tests/Play/Network/Audit20261023TestPlayNetworkHostContractsTests.cs` с тремя проверками: доставка после назначения игрока, request/ack с поздней регистрацией обработчиков, четыре наблюдаемых RPC dispatcher без повторных событий хоста. Создано руководство `Assets/Neoxider/Docs/Testing/NetworkPlayMode.md`, оба package-файла имеют metadata. Это дополнение покрытия; существующие dispatcher-тесты ещё используют локальную ветку.

Другие владельцы уже исправили неограниченные ожидания, восстановление SaveProvider в Money, восемь утечек player-prefab и независимые бюджеты ActionRelay по sender. Повторно реализовывать эти исправления не требуется. Текущий код подтверждает их наличие. Проверены исходники, UTF-8, whitespace, GUID и ссылки; Unity-компиляция, Weaver, PlayMode и удалённые peers не запускались. В 15 исходных файлах остаются 70 методов тестов и 26 scaled waits.

Далее `T` означает `Assets/Neoxider/Tests/Play/Network`, `R` — `Assets/Neoxider/Scripts/Network/Realtime`. Имена после этих обозначений задают точные пути.

## Существенное улучшение: общая тестовая сессия и матрица отдельных peers

**Предложение, не реализация.** Разработчику нужна воспроизводимая ошибка доставки и чистое окружение следующего теста. Повторяемые setup/teardown и DummyTransport этого полностью не обеспечивают.

Ввести test-only `NetworkTestSession : IDisposable` в новом `T/Audit20261023TestPlayNetworkSession.cs`. API: `StartHost(NetworkPeerStage, float): IEnumerator`, `WaitFor(NetworkPeerStage, float): IEnumerator`, `Own(GameObject): GameObject`, `Own(IDisposable): void`, `Stop(): IEnumerator`. Стадии: Connected, Authenticated, Ready, PlayerSpawned, Stopped. Перед захватом проверять чужую сессию/manager/scene identities; отслеживать созданные объекты и подписки, восстанавливать transport, SaveProvider и application settings даже после частичного старта. Stop использует deadline, Dispose обеспечивает аварийное освобождение.

Переиспользовать `NetworkTestHelper`, `NetReadyBroadcast`, `NetClientHandlers`, `NetServerHandlers`, существующий `DummyTransport`, публичные Mirror `RegisterPrefab`/`AddPlayerForConnection` и `ShopPurchasePlayModeTests.MemorySaveProvider`. Аналог NetworkTestSession в текущих tests не найден; новый helper объединяет их lifetime, не заменяет сетевые API. Для обычного gameplay публичный API пакета не меняется.

Минимальная проверка helper: новый `T/Audit20261023TestPlayNetworkSessionTests.cs` проверяет нормальную остановку, частичный startup failure, восстановление настроек после исключения и отказ от чужой сессии без её остановки. Существующие timeout-тесты переиспользуются. Сначала перевести собственный HostContracts fixture, затем основной владелец переводит Bootstrap/ScenePlayer и остальные семь fixtures из таблицы.

Следующий независимый этап: `Assets/Neoxider/Tests/Integration/Network/Audit20261023TestPlayNetworkPeerDriver.cs`, опциональная test-only `Neo.Tests.Network.Integration.asmdef` в той же папке и `scripts/network_playmode_matrix.ps1`. Координатор/CI запускает dedicated server и два настоящих клиента с производственным transport, отдельными портами и deadline каждого этапа. Driver вызывает существующие runtime API и пишет результаты по peer; script собирает evidence и гарантированно завершает процессы. Переиспользовать `NeoNetworkBootstrap`, command-line intent и существующий сценарий запуска; ограниченный первый этап — текущая desktop-платформа. Это будущие файлы, сейчас они не создаются.

Приёмка матрицы: A проходит OwnerOnly, B получает отказ; разрешённая shared-команда B не теряется из-за бюджета A; ServerOnly/AllClients/OthersOnly доставляются ожидаемым peers; поздний клиент получает Money/RPG state; context relay меняет нужного игрока; реальный collider вызывает одно событие; reconnect сохраняет обработчики. Проверять принятые значения и counts, а не только send count. Два CI job должны использовать разные порты. Оценка: 1–2 дня на helper/миграцию и 2–3 на первую peer-матрицу; риск средний, зависит от Weaver, transport и CI lifecycle.

## Порядок, совместимость и завершение

1. После source-final других владельцев обновить snapshot. Исправить PNET-07 с runtime-владельцем и добавить регрессию; параллельное редактирование одних файлов исключить.
2. Исправить legacy dispatcher и локальную очистку, выполнить минимальные регрессии; затем добавить общий helper и заменить ожидания. Runtime ядра Shop/Save/RPG/Physics менять только при выявленном дефекте их контрактов.
3. Реализовать отдельную peer-матрицу. До разделения test assemblies проверить доступность общих типов: root `Audit20261023NeoTestsPlayNetworkWaitTests.cs` использует internal `NetworkTestHelper`. Сохранить рабочие references и GUID; перенос папки Network под новый asmdef сам по себе недостаточен.
4. Обновить существующий `Assets/Neoxider/Docs/Testing/NetworkPlayMode.md` для C# API и scene/NoCode authority, событий и physics-настройки; владельцы добавляют ссылки из `Assets/Neoxider/Docs/Network/README.md` и `Assets/Neoxider/Docs/PlayModeTesting.md`. Координатор создаёт отсутствующий `Assets/Neoxider/Docs/Testing.meta` и metadata новых package-файлов.
5. Проверить import/compile с тестами и без них, Mirror-present/absent; Unity 6.0–6.4 и 6.5+ компилировать соответствующими версиями. Использовать общие `NeoDiagnostics.StableId`/`NeoComponentHealth.StableId`, если потребуется идентификатор; отдельные version gates в тестах не добавлять. Сохранить serialized поля, публичные сигнатуры и sample assets. Текущие `package.json.samples` указывают на `Samples~/...`; проверить также developer `Samples` и imported `Assets/Samples/NeoxiderTools/<version>/<sample name>`, без переименований при тестировании.

Завершение требует фактической компиляции, прохождения затронутых EditMode/PlayMode проверок, ожидаемых receiver payload/count и подтверждённой очистки. Пропуск отсутствующего dev `Mult.unity` остаётся допустимым skip, не сетевым pass. При изменении исходников другим владельцем обновить только зависимую проверку; при недоступной версии Unity/transport оставить соответствующий результат непроверенным. Ограничения raw Mirror replacement и выбор CI transport явно фиксируются координатором; они не задерживают независимые обратимые исправления. В фазе планирования Unity/build/test процессы не запускаются.
